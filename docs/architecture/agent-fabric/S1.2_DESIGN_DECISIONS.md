## 3. S12-F01 — returned resource rejection leaves live ledger divergent

**Historical severity:** MEDIUM. **Evidence class:** OBSERVED.
**Status:** FIXED_AND_ADOPTED by PR #15; design reevaluation resolves the prior dependency.
S12-D11/D12 remain separate design gates.

**Affected:** OP-GRANT-002 and OP-RES-001; subsequent OP-RES-002/003 resource admission;
I-RES-001/003/004 and I-REPLAY-002 ownership, synchronization and live/resume failure-path obligations.
No new grant, permit or excess resource spend was observed. The demonstrated impact is
that a routine rejected reservation prevents subsequent valid resource calls on that
conductor instance, while replay/resume permits the same valid decision.

### Historical trigger and causal chain at `d1e6a1b…`

1. Configure a resource with global limit 1 and a root grant whose resource ceiling is
   at least 2. This is admitted configuration; grant ceiling and global resource limit
   are separate controls. No prior reservation exists for that grant owner.
2. Derive a child requesting 2 units. C records initialization, then enters L.transaction.
   A checks attenuation successfully and asks L.reserve to enforce the global limit.
3. In [resource-ledger.ts](../../../src/forge/agent-fabric/resource-ledger.ts), reserve
   calls bucket(ownerReserved, ownerId) and bucket(ownerConsumed, ownerId) before checking
   global limit. Both mutate empty owner maps. The projected total exceeds the limit,
   so reserve throws AF_RESOURCE_EXHAUSTED before recording a reservation.
4. [authority.ts](../../../src/forge/agent-fabric/authority.ts) deriveExecutionGrant
   catches that exception and returns rejected/af_resource_exhausted. The enclosing
   L.transaction restores only on throw; normal rejected return preserves the new buckets.
5. No grant event persisted those maps. On the next valid derivation,
   [hardened-conductor.ts](../../../src/forge/agent-fabric/hardened-conductor.ts)
   assertLedgerSynchronized compares canonical internal and replay projections and throws
   AF_INVALID_STATE. It does not treat absent and empty owner buckets as identical.
6. A reconstructed HC with a fresh unused seed and the same journal hydrates no such
   buckets. The valid one-unit request succeeds.

At the historical finding baseline, the relevant runtime/schema files were byte-identical to accepted P0a (git diff from
`bfd2639579e650d4ad38ec1a81dbd55a5d68865e` to `d1e6a1bb605527f242b7a6fb6fa05d6ff3561f92` is empty for those paths).
The failure is therefore baseline-derived; these documentary edits do not introduce it.
This finding does not retrospectively change the historical review counts or adoption
event, and cannot be hidden as one of S1.1's fifteen already-dispositioned planning gaps.

### Historical reproduction without modifying runtime or tests

Only on the historical `d1e6a1b…` checkout, from its root with dependencies, pass this module to
`node --import tsx --input-type=module` on stdin (PowerShell here-string or equivalent).
It uses existing synthetic fixtures, creates no network/provider execution and reads
no private fields. It is a historical diagnostic snippet, not the adopted regression oracle. On the repaired
baseline use E-F01 below: its independent journals avoid a successful live append changing
the prefix used by the resumed comparison.

```javascript
import { makeHarness, childRequest, vectorVerifier }
  from './tests/agent-fabric/s11-fixtures.ts';
import { ForgeAgentConductor, ResourceLedger, sha256Digest }
  from './src/forge/agent-fabric/index.ts';

for (const semantics of ['consumable', 'capacity', 'counter']) {
  const h = makeHarness({ definitions: [{ resource: 'units', semantics, limit: 1 }] });
  const rejected = h.conductor.deriveAndRegisterGrant(h.root.grantId, {
    ...childRequest(h, 'too-large'),
    resourceRequests: [{ resource: 'units', amount: 2 }],
  });
  let live;
  try {
    live = h.conductor.deriveAndRegisterGrant(
      h.root.grantId, childRequest(h, 'valid'),
    ).outcome;
  } catch (error) {
    live = error.code;
  }
  const resumed = new ForgeAgentConductor(
    'run:s11', h.journal, h.clock, sha256Digest, vectorVerifier,
    new ResourceLedger(h.definitions),
  );
  console.log({ semantics, rejected, live, resumed: resumed.deriveAndRegisterGrant(
    h.root.grantId, childRequest(h, 'valid'),
  ).outcome });
}
```

| consumable | rejected / af_resource_exhausted | AF_INVALID_STATE | allowed |
| capacity | rejected / af_resource_exhausted | AF_INVALID_STATE | allowed |
