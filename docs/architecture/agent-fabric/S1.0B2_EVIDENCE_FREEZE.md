## 1. Purpose

S1.0B2 freezes the evidence supporting the P0a acceptance event and provides a stable
mapping from the S1.0B1 decisions/invariants to executable implementation and test
surfaces.

The goal is not to claim that tests prove all future Agent Fabric behavior. The goal is to
make the evidence for the **accepted P0a deterministic vertical** independently traceable,
reproducible, and bounded.

## 8. Evidence-to-decision details

### Authority ingress and GoalContract binding

Evidence includes:

- `OwnerAuthorization` contains explicit root execution, goals, subjects, scopes, time and
  budget ceilings;
- `OwnerAuthorizationVerification` content-binds the authorization digest;
- root/child grant checks enforce monotonic scope/attempt/time/resource attenuation;
- grant ancestry currentness checks revocation/expiry and derived reservation currentness;
- hardened permit/replay logic resolves permit → intent → run plan → goal → exact root
  authorization.

Review history demonstrates this was not assumed: cross-root substitution was a prior
BLOCKER and was explicitly remediated/regression-tested before final acceptance.

### Resource resumability/accounting

Evidence includes:

- resource definitions, reservations, consumed/reserved totals, owner totals and
  reservation status represented in control state;
- conductor-owned canonical ledger state rather than caller-owned mutable authority;
- resume hydration from replay;
- fresh/empty ledger substitution unable to erase accumulated journal use;
- conflicting non-empty state failing closed;
- reserve/consume/release replay semantics and negative overcommit tests.

### Live/replay equivalence

Evidence includes:

- authoritative candidate event replay-prevalidation before append;
- pinned transition clock where equality is a protocol invariant;
- stream-global identity/idempotency checks;
- replay-side temporal admission checks;
- replay-side permit/goal authority binding;
- replay-side worker-report digest recomputation;
- negative tests constructed by directly fabricating/mutating journal events.

### Uncertainty and late reports

Evidence includes:

- `AttemptUncertaintyObservation` represented separately from
  `AuthoritativeOutcomeCommit`;
- terminal outcomes restricted to `succeeded | failed`;
- P0a adapter path records uncertainty when a positive report can no longer be admitted
  under current authority;
- regressions verify stale/late positive evidence does not terminalize the intent or block
  a legitimate later retry by itself.

### Canonicalization

Evidence includes the review-driven hardening sequence:

1. own `__proto__` collision discovered;
2. null-prototype canonical object accumulator introduced;
3. strict JSON data-object/array-shape checks introduced;
4. exotic array prototype/inherited `map()` collision discovered;
5. final fix requires `Array.prototype` exactly and reads validated own descriptor values;
6. final independent review accepted the fix with no remaining MEDIUM/HIGH/BLOCKER.

This evidence applies specifically to `forge-canonical-json/v0.1`; it is not evidence of
cross-language JCS interoperability.

## 9. Trust-bound evidence assumptions

The evidence freeze preserves the following assumptions because removing them would change
the accepted protocol claim:

1. **trusted journal origin:** the replay prefix supplied as authoritative comes from the
   trusted journal/storage boundary; the hash chain provides integrity, not origin
   authentication;
2. **trusted owner verifier:** `OwnerAuthorizationVerifier` is in the trusted authority
   boundary and can deterministically verify recorded admission evidence;
3. **trusted resource definitions:** resource definitions/limits used for authoritative
   replay are supplied through the trusted replay context;
4. **trusted semantic validator path:** authority-changing candidate events are admitted
   through hardened validation/replay before authoritative append;
5. **P0a persistence model:** the accepted implementation is an in-memory protocol proof,
   not evidence of production durable transactionality.

## 10. Explicit evidence limitations

The following claims are **not supported** by the frozen P0a evidence and must not be
inferred from the green gates:

- production persistence correctness;
- production journal-origin authentication;
- production outbox exactly-once/transactional delivery;
- real nondeterministic model/provider execution correctness;
- consequential effect resolution/authorization/reconciliation;
- integrity-unknown recovery/authority epoch correctness;
- persistent memory safety;
- adaptive routing/harness compilation safety;
- plugin/evolution promotion safety;
- production deployment/security readiness;
- cross-language canonical digest compatibility.

## 11. Reproduction protocol

For a checkout of the exact accepted head, the minimum repository-level reproduction set
is:

```bash
bun install --ignore-scripts
bun run typecheck
bun test
bun run forge generate
bun run forge verify --standard --script-timeout-ms 120000
npm run release:smoke
```

P0a-focused reproduction can additionally run the Agent Fabric test directory directly.
The exact accepted CI workflow also performs platform/package-manager breadth and external
quickstart checks, while Security Assurance and Nuxt Template Smoke are separate gates.

Reproduction against a later commit is useful regression evidence but is not a substitute
for the historical fact that the merge gate was satisfied on the exact reviewed head.

## 12. Artifact retention rule

This evidence record intentionally stores durable coordinates (SHAs, workflow run IDs,
paths, invariant mappings) rather than depending on ephemeral local review workspaces.

If external independent-review artifacts are later copied into the repository, they may be
linked as supplemental evidence, but doing so must not rewrite the recorded final verdict
or reviewed SHA.
