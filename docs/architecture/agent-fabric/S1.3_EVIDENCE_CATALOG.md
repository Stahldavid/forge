## 2. Record conventions

Every record below resolves the minimum S1.3 evidence fields. Compact tables use these
conventions:

- `subject` = `subject_sha`;
- `workflow head` = `workflow_head_sha` when a workflow exists;
- `workflow base` = `workflow_base_sha` when established;
- `checkout` = `checkout_ref`;
- `checked out` = `checked_out_commit_sha`;
- `exec` = `execution_sha_or_state`;
- `head tree` = `workflow_head_tree_sha`;
- `exec tree` = `execution_tree_sha`;
- `tree eq` = `tree_equivalence_status` plus evidence reference;
- `merge` = `adoption_merge_sha` when one exists;
- `ref` = `source_or_test_ref` plus retained run/log reference;
- `run` = `command_or_workflow`;
- `env` = `runtime_and_environment`;
- `obs` = expected / actual observation;
- `status` = one of `PASS`, `FAIL`, `SKIPPED`, `NOT_APPLICABLE`, `BLOCKED`, `INCONCLUSIVE`;
- `repro` = reproduction status/procedure reference;
- `limits` = limitations and provenance notes.

`CHECKOUT_NOT_ESTABLISHED` is not a failed test result. It is an execution-coordinate
metadata state and must carry `EVIDENCE_METADATA_GAP`. `PROVED_EQUAL` means two recorded
tree SHAs are equal; it does not make two different commit SHAs identical.

For source-only evidence, execution fields are `NOT_APPLICABLE`; no synthetic `PASS` is
invented. The reproduction contract is in
[`S1.3_REPRODUCTION_PROTOCOL.md`](./S1.3_REPRODUCTION_PROTOCOL.md).
