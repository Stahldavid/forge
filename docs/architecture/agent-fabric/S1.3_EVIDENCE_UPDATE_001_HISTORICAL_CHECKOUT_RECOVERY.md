# S1.3 Evidence Update 001 — Historical Workflow Checkout Recovery

**Record ID:** `AF-S1.3-EVIDENCE-UPDATE-001-2026-09-12`

**Status:** `REVIEW_CANDIDATE`; supplements the adopted S1.3-A baseline at `main@de9449648d821086db3d6f214c1a39cd4c659c7e` without rewriting the historical text of the adopted catalog.

## 1. Purpose

The adopted S1.3-A gap register records `S13-GAP-009 — historical GitHub workflow checkout coordinate not established`. Its minimum closure evidence requires recovering the actual checkout ref/commit from the original immutable GitHub job log, recording execution-tree provenance, and never replacing a synthetic merge commit with the associated PR head merely because their trees happen to match.

This update performs that recovery for the historical workflow-backed records explicitly named by `S13-GAP-009`:

- `AF-EV-0001`–`AF-EV-0014` where a GitHub run exists;
- S1.1 vector records `AF-EV-0019`–`AF-EV-0037`, which inherit CI provenance from `AF-EV-0004`;
- specialized corpus records `AF-EV-0038`–`AF-EV-0044`, which inherit P0a CI provenance from `AF-EV-0001`;
- `AF-EV-0045`, which inherits F01 CI provenance from `AF-EV-0007`;
- `AF-EV-0046`, which inherits F02 CI provenance from `AF-EV-0010`.

`AF-EV-0015` remains intentionally `NOT_APPLICABLE` because no Nuxt run was required for the S1.2 documentary diff. Already-recovered S1.3 records (`AF-EV-0016/0017`, `0049/0050`) are not modified by this update.

No result status, test count, historical acceptance decision, normative Agent Fabric rule, source mapping or adoption coordinate is changed here. This update changes only previously-missing execution provenance.

## 2. Recovery rule

For every recovered stage below:

1. the original workflow/job log is the authority for `checkout_ref` and `checked_out_commit_sha`;
2. the Git commit objects are the authority for head and execution tree SHAs;
3. the PR head remains the historical evidence subject/workflow association coordinate;
4. `refs/pull/<n>/merge` remains a synthetic merge execution coordinate even when its tree equals the PR head tree;
5. `PROVED_EQUAL` means content/tree equality only, never commit identity.
