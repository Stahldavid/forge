# S1.3-A — Gap and Tooling Register

**Record ID:** `AF-S1.3-A-GAPS-2026-09-12`

**Status:** `IMPLEMENTATION_CANDIDATE`; not adopted.

**Adopted planning baseline:** `main@801c2192e64652ade19a642b2f09f8660963c74f`.

**Current repository / reproduction baseline:** `main@92c470ae2319aed9bde734d4506767677abe5a3c`.

This register classifies evidence gaps found while building the S1.3-A catalog/matrix and
records whether any gap justifies new tooling. It also preserves independent-review findings
that affect the truthfulness of the evidence package. It does not authorize a test, runtime,
workflow, dependency, timeout or tooling change.

## 1. Gap status semantics

- `OPEN` — the gap is real and intentionally retained.
- `CLOSED` — closure evidence is identified and directly addresses the gap.
- `DEFERRED_APPLICABILITY` — intentional structural/assumption/direction boundary; not a
  defect to be hidden or auto-promoted.
- `BLOCKING_GAP` is a gap **class**, not a requirement that the evidence inventory itself
  remain unadopted. A blocking gap prevents the affected conformance claim/promotion from
  being summarized as supported until separately closed.

No gap is closed merely because a broad CI suite is green.
